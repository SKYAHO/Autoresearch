# Streamlit 가설 등록·상세 화면 분리

## 배경

현재 Experiment Workbench는 가설 작성 패널과 선택한 가설의 상세 관찰 화면을
한 본문에 동시에 렌더링한다. 사용자는 새 가설을 등록하는 작업과 기존 가설의
실행 상태를 관찰하는 작업을 명확히 구분하기 어렵다.

## 목표

- 최초 접속 시 가설 추가 화면을 표시한다.
- 사이드바 최상단의 `+ 가설 추가하기` 버튼으로 가설 추가 화면을 연다.
- 사이드바에서 가설을 선택하면 해당 가설의 상세 화면을 연다.
- 가설 등록에 성공하면 생성된 가설을 선택하고 상세 화면으로 전환한다.
- 가설 상세 화면에서만 실시간 polling을 수행한다.

## 비목표

- Experiment API 요청·응답 계약 변경
- Step·Event·Log 기록 방식 변경
- Streamlit 멀티페이지 구조 도입
- 가설 작성 필드 또는 검증 규칙 변경

## 설계

### 화면 상태

`WorkbenchState`에 현재 본문 화면을 나타내는 닫힌 화면 모드를 둔다.

- `CREATE`: 가설 작성 폼만 렌더링한다.
- `DETAIL`: 선택한 가설의 workbench만 렌더링한다.

화면 모드와 `selected_id`는 독립적으로 관리한다. 사용자가 가설 추가 화면을
열어도 기존 선택과 조회 캐시는 유지한다. 다시 기존 가설을 선택하거나 등록을
완료했을 때 불필요한 초기 조회를 줄이고, 화면 전환 때문에 관찰 상태가
소실되지 않도록 하기 위함이다.

### 사이드바

사이드바의 순서는 다음과 같다.

1. `+ 가설 추가하기` 버튼
2. 실험 목록 새로고침 버튼
3. `실험 기록` 제목과 가설 선택 목록

추가 버튼은 화면 모드만 `CREATE`로 전환한다. 가설 목록에서 다른 항목을
선택하면 기존 선택 전이 로직을 실행하고 화면 모드를 `DETAIL`로 전환한다.
현재 선택된 항목을 작성 화면에서 다시 클릭해도 상세 화면으로 이동할 수
있도록 선택 위젯 이벤트를 화면 전환 의도로 처리한다.

### 본문 렌더링

`CREATE` 모드에서는 가설 작성 패널만 표시한다. 상세 workbench와 polling
fragment는 만들지 않는다.

`DETAIL` 모드에서는 작성 패널을 표시하지 않는다. 선택된 가설이 있으면 기존
workbench와 5초 polling을 유지한다. 선택된 가설이 없다면 사이드바에서 가설을
선택하도록 안내한다.

### 생성 결과와 오류

- 생성 성공: 목록 선두에 새 Experiment를 추가하고 선택한 뒤 `DETAIL`로
  전환한다. 이후 상세 데이터를 한 번 갱신한다.
- 생성 실패: `CREATE` 모드를 유지하고 폼 영역에 API 오류를 표시한다.
- API 설정 오류: 기존 연결 설정 안내를 유지하고 제출을 차단한다.
- 선택한 Experiment가 삭제됨: 선택을 해제하고 목록에서 제거하되 상세 화면에
  선택 안내를 표시한다.

## 테스트

Streamlit 자체 렌더링보다 순수 상태 전이를 우선 검증한다.

- 초기 화면 모드가 `CREATE`인지 검증한다.
- 가설 추가 전이가 선택과 캐시를 유지하는지 검증한다.
- 가설 선택 전이가 `DETAIL`로 이동하며 선택 변경 시 캐시를 초기화하는지
  검증한다.
- 등록 성공 전이가 생성된 가설을 선택하고 `DETAIL`로 이동하는지 검증한다.

## 완료 조건

- 작성 화면과 상세 화면이 동시에 표시되지 않는다.
- 최초 화면은 작성 화면이다.
- 사이드바 버튼과 가설 선택으로 양방향 전환할 수 있다.
- 등록 성공 후 생성한 가설의 상세 화면이 표시된다.
- 상세 화면이 아닐 때 API activity polling이 실행되지 않는다.
